# BUG-002 — Amount field rejects locally formatted numbers with a generic error

**Severity:** Low
**Frequency:** Always
**Component:** Ledger — amount input
**Environment:** Chrome 141, macOS 26, demo app `demo/server.mjs`
**Status:** Open

## Preconditions

- Signed in, on the ledger view

## Steps to reproduce

1. Enter `1.250.000` in **Amount (VND)** — the grouping a Vietnamese user types
2. Fill the note, click **Add**

## Expected

The value is accepted as 1,250,000, or the field rejects the keystroke as it is typed
with a message that names the accepted format.

## Actual

On submit the form shows `Enter a valid number for the amount.` The dot grouping is not
recognised, and the message does not say what format *is* accepted.

## Evidence

`Number('1.250.000')` is `NaN`; the client-side guard in `demo/public/app.js` treats it as
a non-numeric entry.

## Impact

Every user who formats money the local way is blocked at the primary action, and the
message they get does not tell them how to proceed.

## Hypothesised cause

The amount is parsed with `Number()` rather than a locale-aware parse, and the placeholder
(`0.00`) advertises a decimal point in a currency that has no minor unit. Two small
decisions, one dead end for the user.
